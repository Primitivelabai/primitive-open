# Contributing

Thanks for helping. Keep it small and clear.

- Open an issue first for anything big. Small fixes can go straight to a pull request.
- One change per pull request, with a plain description of what and why.
- Tools must stay dependency-free and pass `node --test` in their folder.
- Skills should be generic: no private names, paths, keys or client details.
- Only submit work you wrote or have the right to share under the Apache License 2.0.
- Australian English, plain and short.
